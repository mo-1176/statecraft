# 失敗の扱い

LLM は形式を間違え、ツールは失敗し、API は落ちます。statecraft が、何を作り直し、何を作り直さず、何を利用側に任せるかをまとめます。

---

## 原則

1. **どの終わり方でも、必ず回答を返します。** ループの出口は5つあり、どれも回答で終わります（→ [reference/agent-loop.md](../reference/agent-loop.md)）。
2. **1行・1件の失敗で、全体を止めません。** 記憶の差分は通る行だけ当て、ツールは失敗も結果として返します。
3. **例外を外へ出しません。** tool と委譲の実行は、失敗も `ToolResult` として返します（`Invokable` の約束）。
4. **作り直させるのは、形式の誤りだけです。** 答えの中身の良し悪しで作り直させる仕組みは、本体に持ちません（→ [ADR 0003](../adr/0003-close-by-structure.md)）。
5. **作り直す時は、直す所だけを出させます。** 通った行や、書き起こし済みの実行結果は、もう一度出させません。
6. **判定できなかった時の倒し方は、止めた時に何が起きるかで決めます。** 一律に「安全側」ではありません（下の表）。
7. **回数・待ち時間・逃がし先は、利用側が決めます。** 運用の方針は場面で変わるためです。

---

## 何が起きると、どう扱うか

| 起きたこと | statecraft の扱い | 決めるのは |
|---|---|---|
| 記憶の差分の行が不正（存在しないフィールド、`status` の誤り、空の id） | その行だけを差し戻し、出し直させる | 回数は `max_memory_retries`（既定 3） |
| 差分が JSON の配列として読めない | 実行結果ごと、作り直させる | 同上 |
| システムが書くフィールドへの書き込み | 差し戻さずに捨て、次のステップで1回だけ伝える | — |
| 実行したタスクの `status` が `next` のまま | 差し戻して閉じさせる | 同上 |
| 差し戻しを使い切っても直らない | 止めずに、通った分だけで進む。残りは次のステップで1回だけ伝え、`error` イベントで通知する | — |
| タスクの `target_names` が存在しない・無効化されている | 失敗の結果として記録し、記憶の更新で直させる | — |
| 直前に成功した呼び出しと、全く同じ呼び出し | 実行せずに拒否する | — |
| 必須の引数が空 | 実行せずに、「必須の引数が空」という失敗の結果を記録する | — |
| ツールが例外を投げた | 失敗の結果にする。LLM へは汎用の文だけを返す | 中身を見せるかは `expose_error_details` |
| ツールの戻り値の形が違う | 失敗の結果にする。何がおかしいかを LLM へ返す | — |
| 直前のステップと全く同じ実行の繰り返し（停滞） | 1回目は `STALL_NOTICE` を見せて立て直させ、続けば打ち切って回答する | 回数は `max_stalled_steps`（既定 2） |
| `max_steps` を使い切った | 打ち切って、そこまでの情報で回答する | `max_steps`（既定 10） |
| 実行されないまま残ったタスクがある | 回答の生成に「実行されていないタスク」として知らせる（止めはしない） | — |
| 最終回答が `output_schema` の形として読めない | 1回だけ作り直させる | — |
| 生成が API のエラーで失敗した | 既定では再試行しない | `recover.generation_failed` |
| 予算などの理由で生成を止めたい | `GenerationAborted` を投げる | `guard.before_generate` |
| 実行を止めたい | その1件だけを拒否し、理由があれば LLM へ渡す | `guard.before_execute` |
| 記憶の更新の中身が気になる | 差し戻して、指摘を踏まえて直させる | `guard.before_memory_diff`。上限も利用側（組み込みの監査役 `enable_auditor` は2回） |

---

## 記憶の差分の作り直し

記憶の差分は、作り直しの回数が一番多い所なので、無駄を減らす工夫が多く入っています。

- **失敗した行だけを出し直させます。** 通った行はすでに記憶に入っています。全体をやり直させると、正しく書けた項目まで作り直すことになります。
- **作り直しには、実行結果を渡しません。** 書き起こしは、当てた記憶にすでに済んでいます。配列として読めなかった時（1行も当たっていない時）だけは、実行結果ごと作り直させます。
- **差し戻しの文は毎回作り直します。** 前回の文に積み増すと、直った古い失敗まで見せ続けることになります。
- **直せないものは差し戻しません。** システムが書くフィールドへの書き込みのように、差し戻しても直らないものは、再生成のトークンを使わせずに捨て、次のステップで1回だけ伝えます。

### 監査による差し戻し

`guard.before_memory_diff` を登録すると、差分を当てる前に監査に見せられます。差し戻すと、その差分は1行も当てずに持っておき、**直す行だけ**を同じ `field` と `id` で出させます。出さなかった行は、持っておいた差分のまま当たります。作り直しには実行結果を渡しません。

監査の差し戻しは、形式の差し戻し（`max_memory_retries`）とは別に数えます。**差し戻しの上限は、フレームワークが持ちません。** 何回で通すかは、監査する側が `review_round` を見て決めます。毎回差し戻す監査を登録すると、同じ更新が作り直され続けます。

組み込みの監査役（Network の `enable_auditor`）は、監査する側として自分の上限を持ちます。2回差し戻したら、次の差分は監査せずに通します。

## 判定できなかった時の倒し方

guard と recover は、決まった型（`ExecuteDecision` など）で返します。型の違う値を返した時や、例外を投げた時の倒し方は、窓口ごとに違います。

| 判定 | 型の違う値・例外 | なぜその向きか |
|---|---|---|
| `before_execute` | **拒否** | 判定できなかった実行が「許可」として通ってはいけない |
| `before_generate` | **中止**（`GenerationAborted`） | 予算の判定が壊れた時に、生成を続けてはいけない |
| `before_memory_diff` | **その監査を飛ばす** | 上限をフレームワークが持たないので、差し戻しに倒すと、壊れた監査が同じ更新を作り直させ続ける |
| `generation_failed` | 型の違う値は「その関数は再試行しない」、例外は「諦める」 | 再試行は利用側が明示した時だけ |

---

## 理由の返し方

`before_execute` で止める時、理由（`reason`）は LLM へそのまま渡ります。

- 引数を直せば通るもの（形式の誤り）や、条件が分かれば諦められるもの（営業時間外）は、理由を返します。
- **理由に「何なら通るか」は書きません。** 形式を教えると、その形式に合わせて値を作られます（「会員番号は M- で始まります」と返すと、「12345」が「M-12345」に書き換えられて実行される）。
- 理由そのものが審査基準になる場合は、理由を付けずに拒否します。

形式のチェックだけでは、形を真似た値が通ります。**実在の確認や権限の確認は、ツール本体で行ってください。** LLM に審査させる方法は、機械的な条件では書けないものにだけ、重ねる層として使います。
